# 0.3.3 성능 확인

0.3.2와 같은 시험 대화를 사용한 로컬 측정입니다. 실제 Discord 서버 응답 시간, Electron 화면 그리기 시간, 앱 전체 CPU·메모리 사용률의 개선율을 뜻하지 않습니다.

| 검사 | 0.3.2 | 0.3.3 |
| --- | ---: | ---: |
| 기존 200개 + 새 메시지 30개, UI 콜백 처리 중앙값 | 2,260ms | 338ms |
| 메시지 200개 DOM 조회 중앙값 | 78.87ms | 51.39ms |
| 같은 DOM 조회의 스타일 조회 횟수 | 3,615 | 216 |
| 같은 DOM 조회의 복사 횟수 | 402 | 21 |
| 변화 없는 상태 조회 20회의 상태 IPC | 20 | 0 |
| 변화 없는 상태 조회 20회의 창 배치 호출 | 20 | 0 |
| Windows portable 실행 파일 | 126,572,671 bytes | 116,975,604 bytes |
| 압축 해제한 Windows 앱 | 374,492,157 bytes | 324,625,761 bytes |

UI 측정은 JSDOM에서 준비 작업을 제외하고 세 번의 시험 중앙값을 사용했습니다. DOM 조회 시간은 아홉 번의 시험 중앙값입니다. 최종 코드 줄 수·요소 수·메시지 내용은 같고, 기존 노드를 새 메시지마다 다시 만들지 않습니다.

활성 창의 700ms 조회 간격은 유지합니다. 최소화·숨김 시 주기 조회는 멈추지만 Discord 연결 자체를 종료하지 않으며, 복원 시 즉시 최신 상태를 읽습니다. 전송과 대화 전환에 필요한 명시적 조회는 그대로 수행합니다.

Windows 빌드에는 한국어와 영어 Electron 언어 리소스만 포함합니다. 실행 엔진과 Discord 웹이 사용하는 기본 메모리는 남아 있으므로, 이 최적화가 앱 전체 메모리를 특정 비율로 줄인다는 보장은 하지 않습니다.

## 0.3.5 추가 정리

- 200개 채널·2개 카테고리의 로컬 DOM 시험에서 카테고리 제목 탐색을 10,100회에서 200회로 줄였습니다. 재사용 범위는 동기 조회 한 번이며 다음 조회에는 이름 변경·이동·삭제가 반영됩니다.
- 메시지 시간 표시는 같은 한국어 날짜 형식기를 재사용합니다. 첨부 이미지 미리보기는 글자 위를 이동할 때 다시 로딩하지 않으며, 닫을 때 이미지 주소를 해제합니다.
- 이미 배정한 코드 파일명은 다시 정렬하지 않고 새 대화에만 이름을 배정합니다.

이 수치는 특정 DOM 작업 횟수이며 앱 전체 CPU·메모리 사용량이나 네트워크 속도의 감소율이 아닙니다. Electron과 Discord 웹의 실행 엔진 크기는 유지했습니다.

## 0.3.8 전송 확인 개선

- 전송 확인은 `sendSnapshot()`으로 현재 대화와 입력창만 읽으며, 서버·채널 목록과 대화 제목을 다시 탐색하지 않습니다. 메시지와 첨부 정보는 계속 갱신합니다.
- Enter를 보낸 뒤 첫 결과 확인은 즉시 시작합니다. 기존에는 첫 확인 전에도 200ms를 기다렸습니다.
- 전송 처리와 코드 화면이 같은 메시지 비교 함수를 사용합니다. 굵게·기울임·코드 등 지원하는 서식 때문에 입력 문자열과 표시 문자열이 달라져도 전송 결과를 확인할 수 있습니다.
- 확인 응답이 늦으면 전송 시작 후 60초까지 새 스냅샷에서 결과를 확인합니다. 성공이 확인되면 입력 잠금을 자동으로 해제하며, 사용자가 수정한 초안은 보존합니다. 자동 재전송은 하지 않습니다.

이는 조회 범위와 확인 절차의 변경입니다. 실제 Discord 네트워크 응답 시간이나 앱 전체 CPU·메모리 사용량의 개선율을 측정한 결과는 아닙니다.

## 0.3.9 입력 대기 분리

- Discord의 정상 입력창이 비워지면 다음 메시지 입력을 허용합니다. 서버 확인은 별도로 이어가며, 확인 전에는 성공으로 표시하지 않습니다.
- 실패·미확인 메시지의 원문을 메모리에 남겨 빈 입력창에 복원할 수 있습니다. 같은 내용을 연속 전송해도 하나의 메시지를 두 번의 성공으로 계산하지 않습니다.
- 입력 상태 검사에도 동기 조회 한 번 동안만 표시 여부 캐시를 적용합니다. 200개 메시지의 로컬 DOM 시험에서 스타일 조회 횟수는 상태 확인 1,406→209회, 포커스·전송 각각 2,824→430회로 줄었습니다. 포커스와 키 이벤트로 DOM이 바뀐 뒤에는 새로 확인합니다.

이 수치는 로컬 DOM 작업 횟수이며 실제 Discord 서버의 응답 속도를 측정한 값은 아닙니다.

격리된 Electron 시험에서 메시지 표시를 10.5초 지연시켰을 때, 최종 배포 코드의 다음 입력 준비 시간은 121ms였습니다. 뒤늦게 확인이 도착해도 작성 중인 새 초안은 유지됐습니다. 로컬 모의 대화에서의 관찰이며 실제 네트워크 지연 측정은 아닙니다.
