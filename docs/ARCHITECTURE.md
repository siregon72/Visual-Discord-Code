# Visual Discord Code 구조

## 실행 흐름

```text
live.html + styles.css
  └─ src/renderer/* + live.js
       └─ preload.js (제한된 IPC API)
            └─ src/main/ipc.js
                 └─ src/main/controller.js
                      ├─ adapter-client.js → Discord WebContentsView
                      │                       └─ discord-adapter.js
                      └─ send-message.js → 사용자 요청 1회 전송 및 결과 확인
```

`main.js`는 Electron 시작, 창 생성, 종료 정리를 담당합니다. Discord 연결과 진행 중인 작업은 컨트롤러가 관리합니다. UI는 Electron이나 Node에 직접 접근하지 않고 `window.vdc`에 공개된 기능만 사용합니다.

## 유지해야 하는 경계

- Discord 연결은 공개된 웹 화면의 DOM만 읽습니다. 토큰, 내부 저장소, 비공식 메시지 API에 접근하지 않습니다.
- 코드 화면과 Discord 웹 화면 모두 Node 접근을 차단하고 context isolation과 sandbox를 유지합니다. IPC는 승인된 로컬 문서의 최상위 프레임만 받습니다.
- 샌드박스 preload에서 프로젝트 내부 CommonJS 모듈을 직접 불러오지 않습니다. 제한된 `electron` API만 사용합니다.
- 외부 링크는 자격 증명이 없는 HTTP(S) 주소만 허용합니다. 임의 로컬 프로토콜은 실행하지 않습니다.
- 메시지는 코드처럼 보이는 문자열로 렌더링할 뿐 실행하지 않습니다. 텍스트와 메타데이터는 HTML로 해석되지 않도록 처리합니다.

## 연결과 작업 상태

컨트롤러는 게스트와 문서의 세대를 구분합니다. 로그아웃, 문서 이동, 연결 교체나 종료 이전에 시작한 요청이 나중에 완료되어도 현재 화면을 덮어쓰지 않습니다. 중복 스냅샷 조회는 합치고, 오래 걸리는 어댑터 호출은 시간 제한으로 종료합니다.

연결 준비 여부와 전송·대화 전환·로그아웃 작업 상태를 UI에 전달합니다. UI와 메인 프로세스가 모두 전송 가능 여부를 확인하므로 버튼 표시만으로 전송 권한이 결정되지 않습니다. 일시적인 읽기 실패는 오류로 표시하고, 다음 정상 읽기에서 복구합니다.

## 수동 전송의 순서

1. 요청의 대화 주소와 텍스트 길이를 검사합니다.
2. 현재 대화, 준비된 입력창, 열린 대화상자와 기존 Discord 초안을 확인합니다.
3. 입력창에 실제 메시지 원문을 넣고, 대화·포커스·입력 내용과 연결 상태를 다시 확인합니다.
4. `submitComposer()`가 같은 대화·입력창·작성 내용을 다시 검증하고 해당 편집기에 Enter `keydown`을 한 번 전달합니다. 처리되지 않았고 같은 초안이 남아 있을 때만 `keypress`를 이어 보내며, 마지막에 `keyup`을 전달합니다. 화면 밖의 내장 뷰로 OS 키 입력을 보내던 경로는 사용하지 않습니다.
5. 전송 전에 없었던 본인 메시지와 보류·실패 상태, 입력창 비움 여부로 결과를 확인합니다. 성공이 아직 확인되지 않았더라도 Discord가 정상 입력창을 비운 경우에는 접수 상태로 반환하고 다음 입력을 허용합니다. 입력창이 사라지거나 확인할 수 없는 상태는 접수로 처리하지 않습니다.

자동 재전송은 하지 않습니다. 입력 후 연결이 바뀌거나 결과를 확정하지 못하면 불확실한 전송으로 반환하고 초안을 보존합니다. 시간 제한이나 작업 취소 이후 늦게 도착한 결과가 Enter를 발생시키지 않도록 각 비동기 단계에서 작업 유효성을 검사합니다.

전송 중에는 `sendSnapshot()`으로 현재 대화만 확인하고 전체 서버·채널 목록 조회를 쉬어 갑니다. 전송 여부는 `src/shared/message-receipt.js`의 공통 규칙으로 확인합니다. 접수된 메시지는 원문과 확인 근거를 메모리에 보관하고, 다음 입력을 막지 않은 채 최대 60초 동안 결과를 확인합니다. 결과를 확인하지 못하거나 실패가 표시되면 원문 복원 기능을 제공합니다. 새로 작성한 초안은 덮어쓰지 않습니다. 즉시 확인된 결과도 렌더러에서 순서대로 대조하며, 같은 메시지 ID가 여러 전송의 성공으로 계산되지 않도록 이미 사용한 ID를 공유합니다.

## 화면과 초안

`src/renderer/state.js`가 대화별 초안과 상태를 관리합니다. 문서가 잠깐 비는 연결 과정은 계정 초기화와 구분합니다. 계정 초기화 이후 도착한 이전 전송 응답은 새로운 초안을 지우지 않습니다. 초안은 메모리에만 저장하며 앱 종료 시 사라집니다.

`src/renderer/code.js`는 메시지 ID에 따라 안정적인 React 코드 표현을 만듭니다. `state.js`는 대화방 방문마다 최초 준비된 기록과 이후 새 메시지 ID를 구분합니다. 새 메시지는 문서 끝 `// New messages` 아래 한 코드 줄로 표시하고, 대화 주소 변경·계정 초기화·앱 재실행 시 방문 상태를 초기화합니다. 일시적인 읽기 실패나 기록 스크롤은 방문을 초기화하지 않습니다. 이전 기록을 불러오거나 새 메시지가 추가되어도 같은 방문 중 이미 표시한 메시지의 표현은 유지됩니다.

새로 나타난 메시지의 시간과 방문 시작 시간을 비교해 과거 기록 페이지를 새 메시지로 분류하지 않습니다. 시간이 없는 행은 알려진 기록 뒤에 추가된 경우만 새 메시지로 처리합니다. 전송 중 임시 ID가 확정 ID로 바뀌면 본인 메시지 내용·첨부와 가까운 시간을 확인해 한 줄 표현을 유지합니다. 이 분류는 메모리에만 있고 실제 전송이나 Discord 기록을 바꾸지 않습니다. `explorer.js`는 실제 서버·대화 목록을 표시합니다.

상단 메뉴·검색·레이아웃 아이콘과 지정된 왼쪽 아이콘은 의도적으로 장식 전용입니다. 새 기능을 연결할 때 사용자 요구 없이 다시 활성화하지 마세요.

Explorer의 `⋯`는 대화 이름/코드 파일명 표시 전환입니다. `file-names.js`가 대화 주소별로 고유한 `.jsx`/`.tsx` 파일명을 배정하고, 탐색기·탭·경로가 같은 공급자를 사용합니다. 실제 대화 열기와 전송은 원래 주소를 사용합니다. 파일명과 표시 설정만 로컬 저장소 `vdc.file-names.v1`에 보관하며, 저장소 접근이 실패해도 메모리에서 계속 동작합니다. 목록 정렬이나 새 대화 추가는 이미 배정한 이름을 바꾸지 않습니다.

## 반복 작업 최적화

- Discord DOM에서 표시 여부와 메시지 목록은 동기적인 스냅샷 한 번 안에서만 재사용합니다. 반환 후 폐기하므로 다음 조회나 입력창 포커스 검사에는 이전 DOM 결과가 남지 않습니다.
- 어댑터 설치 후에는 짧은 호출 코드만 전송합니다. 새 문서에서 어댑터가 없다는 응답을 받은 경우에만 같은 시간 제한 안에서 다시 설치합니다. 이미 실행된 동작이나 시간 초과를 자동 재시도하지 않습니다.
- 변경 없는 상태 IPC와 동일한 창 배치를 생략합니다. 명시적인 렌더러 상태 요청에는 항상 응답합니다. 최소화·숨김 중에는 주기 조회만 멈추고, 복원·표시 시 바로 조회합니다.
- 기존 기록과 새 메시지 앞부분이 동일하면 새 메시지 DOM만 추가합니다. 수정·삭제·기록 로딩·대화 전환·계정 변경 시 전체 표현을 다시 계산합니다.

## 변경 확인

```powershell
npm ci
npm run validate
npm run test:desktop
npm run dist
```

- `validate`: 문법, 파일 구성 및 단위·DOM 회귀 검사
- `test:desktop`: 별도 프로필과 로컬 Discord 모양의 시험 문서에서 실제 Electron 입력·전송 경로 확인. 실제 계정에 메시지를 보내지 않습니다.
- `dist`: 필수 파일 검사 후 아이콘을 포함한 Windows ZIP 배포 파일 생성

Discord의 DOM이 바뀌면 `discord-adapter.js`와 DOM 시험 데이터를 먼저 수정합니다. 소스 폴더에 사용자 세션, 쿠키나 실제 대화 덤프를 추가하지 마세요.

## 0.3.5 보완

메인 문서의 실제 교체와 SPA 대화 이동만 작업을 무효화하고, 임베드 프레임 로딩은 진행 중인 전송을 취소하지 않습니다. Ctrl/Cmd+R은 기존 새로고침 작업 제한을 따르며 코드 렌더러를 재시작하지 않습니다. 기록 조회는 읽기 권한과 전송 권한을 구분하여 읽기 전용 채널에서도 가능하고, 작업 중·로딩·대화상자 상태에서는 차단합니다.

Windows 패키징은 signAndEditExecutable:false를 사용하여 Electron 실행 파일을 그대로 유지합니다. 앱 전용 아이콘은 BrowserWindow와 바탕화면 바로가기에 적용합니다. ZIP 배포의 모든 파일을 함께 보관해야 하며 EXE 하나만 복사하면 실행할 수 없습니다.

원본 Windows 실행 파일을 유지하려고 빌드 시 ASAR 해시를 EXE 리소스에 삽입하는 단계도 생략합니다(disableAsarIntegrity:true). Electron 퓨즈나 운영체제 보안 정책을 변경하지 않습니다. 배포 시 ZIP CRC·파일별 원본 비교·ASAR 해시·SHA256SUMS로 최종 파일을 검증합니다.
